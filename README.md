## System Overview

An agent joins a voice call on Mezon and, around that call, this project provides:

- **Real-time speech-to-text** per participant track, streamed out as the call happens.
- **Text-to-speech played back into the call** when a room's agent is configured to speak (e.g. for live translation).
- **Durable call recording** to object storage, plus a client-playable transcoded copy for later playback.
- **Post-call meeting summaries**, generated by an LLM once a call ends.
- **A web dashboard**, authenticated via Mezon OAuth2, for browsing rooms, live/finished transcripts, and summaries.

Rather than one monolith, this is a set of small, independently-run Go and Python services — see [Architecture](#architecture) and [Core Components](#core-components) below for how they fit together.

### Key Technologies

- **[Mezon](https://mezon.ai)** — the chat/voice platform calls happen on; this project is a set of services built around it, not a fork of it.
- **[mezon-sfu](https://github.com/mezonai/mezon-sfu)** — the in-house WebRTC SFU (Selective Forwarding Unit) that actually carries call media (audio/video/screen). It's the communication/media platform this project's call agent connects to.
- **Go** — the call agent (`agents/`) and the Mezon bot/identity bridge (`agents-bot/`).
- **Python + FastAPI** — the backend service cluster (`orchestrator_service`, `stt_service`, `tts_service`) under `Architect_MultiClient_Server/`.
- **[Nemotron](https://huggingface.co/onnx-community/nemotron-3.5-asr-streaming-0.6b-onnx-int4)** — cache-aware streaming ASR model used for live, per-track transcription.
- **faster-whisper** — batch transcription engine used once a full recording is available.
- **[Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M)** — text-to-speech model used when the agent speaks into a call.
- **PostgreSQL**, **Redis**, **MinIO (S3-compatible)** — datastore, stream/queue dispatch, and recording storage.
- **React + Vite** — the dashboard frontend.

## Architecture

```
Mezon (chat/voice)                          mezon-sfu (WebRTC SFU)
   │  bot login, chat events                    │  media (audio/video/screen)
   ▼                                             ▼
agents-bot ◄──identity/roster/chat────►  agents/cmd/agent (one per call)
   ▲                                             │  │
   │ NATS start/stop                             │  ├─▶ audio-ingestion/record-service ──▶ MinIO/S3
agents/cmd/worker-manager ────spawns/kills────────┘  │        │ recording.completed
                                                      │        ▼
                                                      │   orchestrator_service ──▶ audio-processing-service (transcode)
                                                      │        │  Postgres (rooms/transcripts/summaries)
                                                      ├─▶ stt_service (realtime, per track)
                                                      │        │  also: batch Whisper pass, triggered by orchestrator_service
                                                      └─▶ tts_service (when the agent speaks)
                                                               │
                                                       dashboard ── reads rooms/transcripts/summaries, SSE for live updates
```

Every arrow above is HTTP, WebSocket, gRPC, SSE, or a Redis Stream — these components do not import each other's code. See each directory's own README for the exact protocol/contract; this diagram is deliberately a simplification (e.g. it omits the two independent STT paths inside `stt_service`, and the exact recording/derivative event handshake with `orchestrator_service`).

## Core Components

1. **[`agents`](agents/README.md)** (Go) — the call agent: `cmd/agent` (one process per call, joins `mezon-sfu` over WebRTC, forwards audio to `record-service`/`stt_service`, plays TTS back) and `cmd/worker-manager` (subscribes to NATS start/stop events and spawns/kills `agent` subprocesses).
2. **[`agents-bot`](agents-bot/README.md)** (Go) — a long-lived bot process logged into Mezon itself, filling the identity/chat gap `mezon-sfu` doesn't cover: resolves Mezon user profiles and bridges inbound chat to `orchestrator_service`.
3. **[`orchestrator_service`](Architect_MultiClient_Server/orchestrator_service/README.md)** — the central coordination layer: registers rooms/calls, receives recording-lifecycle events, dispatches STT/transcode work over Redis Streams, persists transcripts/summaries to Postgres, and pushes live updates over Server-Sent Events.
4. **[`stt_service`](Architect_MultiClient_Server/stt_service/README.md)** — speech-to-text, two independent paths in one deployable: realtime streaming (Nemotron, WebSocket, fed by the Go agent) and batch/offline transcription (faster-whisper, Redis Streams, triggered by `orchestrator_service` after a recording finishes).
5. **[`tts_service`](Architect_MultiClient_Server/tts_service/README.md)** — text-to-speech (Kokoro-82M), a single HTTP endpoint the Go agent calls when a room's agent speaks.
6. **[`dashboard`](Architect_MultiClient_Server/dashboard/README.md)** — the React/Vite admin UI for browsing rooms, transcripts, and summaries.
7. **[`audio-ingestion`](audio-ingestion/README.md)** — call audio capture and playback-format transcoding, split into two independently deployed services: **[`record-service`](audio-ingestion/record-service/README.md)** (critical path — captures raw audio to MinIO/S3) and **[`audio-processing-service`](audio-ingestion/audio-processing-service/README.md)** (async — transcodes it to a client-playable format).

## Features

### Call handling
- Joins a Mezon voice call as a bot participant and records the call's audio.
- Optionally speaks into the call (text-to-speech), for use cases like live translation playback.
- Bridges inbound Mezon chat into the call context via `agents-bot`.

### Transcription & translation
- Real-time, per-track speech-to-text while the call is in progress.
- A separate batch transcription pass over the full recording once a call ends, independent of the realtime path.

### Recording, summaries & dashboard
- Durable raw audio capture, plus an async transcoding pipeline that produces a client-playable derivative file.
- End-of-call meeting summaries generated via an LLM.
- A web dashboard (Mezon OAuth2 login) for browsing rooms, transcripts, and summaries, with live updates over SSE.
